The assistant has read the production code, so it is not independent of the implementation (blueprint O8); this table is built from the requirement entries alone and makes no claim about what the code does.

Source: `REQUIREMENTS.md` at main, SHA-256 fa2580d6bf0a67dd80d5e569da363776a029a79caef457604c7efe74ea72f7bc. It holds 55 requirement IDs, each in one row below, none missing or duplicated.

Blueprint 1.1 and the Phase 1 exit criteria require every ID to be marked in scope or out of scope, with an owner decision, before Phase 1 closes. A requirement outside scope is listed as not certified, and none is excluded merely because it is inconvenient to prove. "Not yet scoped" is allowed only before closure.

## What this proposal is

- Proposed scope for every row is **in scope**. No row is proposed as out of scope, so nothing is proposed as "not certified" at this stage.
- Rows marked **Owner attention** are in scope as proposed, but certifying them would need access to something outside the repository (shown in the note). The owner may keep them in scope with the limit recorded, or mark them out of scope as not certified. The assistant proposes neither.
- The Owner decision column is **Pending** on every row. Approval, row by row or as a whole, is the owner's; it is recorded afterwards in `AUDIT.md`, not by this file.
- The Applicable claim, Evidence method and Certification status columns belong to Phases 3 and 5 and stay empty.
- This file proposes no state model, no transition boundary, no R1 to R5 answer, and no reading of any requirement text.
