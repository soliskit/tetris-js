## SAVE-1 and VALID-1 evidence reconciliation

The retired [audit blueprint](https://github.com/soliskit/tetris-js/blob/1354e7711d02070b0f6d54849646657e1965aeef/docs/audit/audit-blueprint.txt) defines Phase 8 in section 8 and persistence ordering in property O4. Persistence ordering means preserving the required last-good saved representation until the transition has passed the required validation boundary. Those existing criteria govern this reconciliation.

Read-only reconciliation on November 4, 2026. The Pending work labels above remain unchanged. Supported implementation evidence is separate from the historical proof needed for the re-proof and re-falsification phase (Phase 8); this record does not certify a phase or a live deployment.

The ten compared files are public/game/session.js, public/game/gameManager.js, docs/requirements.md, docs/decisions.md, test/savedRecord.test.js, test/semanticSave.test.js, test/session.test.js, test/gameManager.test.js, e2e/save-publication.spec.js and e2e/serialization-failure.spec.js. They have equal contents at correction merge 5a2076ae800455702e05e46fc646b785069a2dfa ([#458](https://github.com/soliskit/tetris-js/pull/458)) and main 3a7fc669801422c627649cedb34b4a8da7ab7365. This transfers those contents, not an environment or deployment identity.

- SAVE-1: source and witness bodies support complete validated-record publication, construction and validation before writing, availability withdrawal with exact position-string retention, refused-write byte retention, local withdrawal, rejected-content retention, no writes on absent or unreadable reads, fresh Continue validation, and completed-save retention after an engine fault. Serialization-failure witnesses cover successful and refused withdrawal. Browser witnesses cover Continue visibility. These are injected-failure witnesses, not physical-quota or ordinary-play fault claims. At the pause-save route, a game-written save validated by the independent oracle is preserved byte-exact through a refused rewrite and revalidated after (PR #480); the other save routes keep refusal witnesses whose preserved bytes are not independently validated.
- VALID-1: source and witness bodies support the stored-score range without divisibility, full-row acceptance, required exact history, count 0 through 16 with 16 resting, the greatest-occupied-row lower bound and deeper historical-row allowance. Restore is paused and retains exact history. The independent snapshot-validity predicate uses retained geometry rather than the production parser or cell method; production GameManager, actions and helpers generate its inputs. It is not an independent transition model or an all-state proof.
- Corrected-suite evidence: the successful [merge test job](https://github.com/soliskit/tetris-js/actions/runs/41527580671/job/125559174398) and [plain-runner job](https://github.com/soliskit/tetris-js/actions/runs/41527580627/job/125559174601), together with the command and suite identity at the merge, support aggregate passing at that source. The workflow checks require a nonempty unit suite with no unit skips and a nonempty browser suite within its expected skip set; its skip-identity check passed. Individual witness logs were not recovered in this reconciliation. A separate log for every test is not added as a phase-exit criterion.
- Historical pre-fix evidence: an earlier November 2 pre-fix run reported 27 cases, with 19 failures and 8 passes. The surviving test text and partial per-test results include a behavioral mismatch as well as failures from missing APIs. That run used the earlier two-key design; it does not by itself establish FAIL-before for the later saved-record envelope. The exact corrected-envelope regression failing against the pre-fix implementation was not found in the records examined for this reconciliation. Not all historical jobs, artifacts or other copies were checked. The original full output file was not retrieved. That bounded search does not establish that no such run exists. These earlier failures are not a current runtime result. Source reading confirms that the earlier parser rejected scores not divisible by 100; it is not a recovered runtime demonstration for every valid-save boundary.
- Phase 8 gap: intended-property evidence, affected-failure-mode evidence and O4 ordering/persistence fit remain supported at their stated scope. The blueprint requires the original regression to fail against the pre-fix implementation and pass against the corrected implementation. The earlier run does not alone fill the final-envelope gap. Unqualified Phase 8 closure is not established.

Concurrent or cached writers, non-atomic read-then-withdraw, browser termination and resource exhaustion remain written limits. Deployment identity is unverified; this record makes no shipped/current-live claim. No requirement, finding status or phase-exit criterion changes here.
