# Revision 3 note. Revisions 1 and 2 are frozen and untouched. Inputs: the four supplied files only.

## Corrections
1. GEOM T state 3 was wrong (typo, equal to Z state 3). Now (0,1),(1,0),(1,1),(2,1) per the supplied table. Revision 1's claim that all non-O entries matched covered the image-vs-table comparison, not GEOM-vs-table; GEOM was not checked then. selftest_rev3.py now parses the supplied table text and asserts all 28 GEOM states equal it (passes). Revisions 1 and 2 carry the T3 error.
2. Opening state: the model now needs `choices['opening_queue']` (3 kinds) and raises Undefined('A9') without it, since B1 applies R1 to the opening state and B7 requires three valid pieces. With a supplied queue the opening state passes valid_state (tested).
3. valid_state widened (B3 strict types, B12 for every mode): confirmation pending only while paused (now also checked at game over); held tokens are unique (token, left|right|down) pairs; repeat values in {idle, waiting, repeating} and {idle, dropping}; non-idle repeat only while playing with a matching held direction; touch state shape, and control only while a piece exists; at game over touch is None and no current piece. Strict type checks (no bools as integers, string kinds, lists) added. At ordinary game over the model normalises held, hold-used, bag, reset count and lowest row to None; the sources only say they have no semantic value (not required to be cleared).
4. last_gravity_request_s removed. The sources define only the derived interval (B14, S10). `gravity_interval_s()` returns it while gravity runs. When the scheduler request is re-issued (start, spawn, resume, level change) is not specified beyond the PLY-3 restart: ambiguity A16, no claim made.
5. A10 now needs caller choices `suppress_on_start` and `suppress_on_blur` (else Undefined('A10')). Only resume suppression is defined (C3, E2, E3) and stays fixed. Continue needs no rule since the following resume applies C3.
6. Touch excursion: single source of truth is the `never_beyond_10px` and `ends_within_10px` arguments of touch_end (E1). Move/drop calls no longer set any excursion flag.
7. continue_available includes validity because D20 section 1.2 item 5 (Continue availability) says it is true only when the eligibility value is "true", item 16 is false and the saved game passes the validity rules. That is sourced, not a model reading. The part that remains a reading is A17: when Continue is pressed on an eligible but invalid save, the model withdraws it (SAF-1 "rejected whole and forgotten"). A17 is this model's own label for that reading, not a decision in the pack. Because availability already requires validity, the press path is only reachable if a caller bypasses availability.
