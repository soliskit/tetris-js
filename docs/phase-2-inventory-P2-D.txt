CANDIDATE OBSERVATIONS, NOT FINDINGS OR STATUSES

- A14 direct touch begin/update/end/reset and A11 DOM-focus selection routes require explicit boundary mapping; nested guarded gameplay is not a guard around all control commits.
- softDrop clears A10 before guard; dispatcher clears it for every action before mode checks. These side effects need operation/frame accounting.
- drawSafely does not cover bootstrap probes, rAF registration, observer entry/sizing, resolution setup/re-registration, viewport setup or async wake callbacks. Poll try does not cover rAF registration. requestDraw/polling mark pending before registration. Later faults could stall those paths; no fault injected here.
- Actual notification paths are engine/draw/poll console reports and engine faults array; no player-facing error notice hook in the two page files. Reporting compliance is not classified here.
- Drawing uses storage getters/cache, but does not accept saved payload into authority. P2-B must map A16 and derived availability independently of getter names.
- No mode check in pointerdown; no lostpointercapture listener; no visibility resume. These are route inventory facts, not new requirements.
