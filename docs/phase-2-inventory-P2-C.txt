7. Candidate observations (labeled candidates; not findings; compare against D16/D32-D34 in later phases)
7.1 Items 11-14 live outside the engine (see 6). Unlike item 10, the commit point for ops 2, 4-9 is not inside the engine guard.
7.2 Item 12 representation: no ordered token list; ordering is fixed priority KeyA > KeyD > pad IC:246-248 (compare D32 op 5 "last remaining token wins", B12; D34 E3 says representation left open).
7.3 Pause/resume with held controls (compare D33 C3, D34 E2/E3): heldKeys/padDirection/padDown/heldButtons are not cleared on pause (only blur/disconnect IC:87-88, 305-312). movement repeat self-stops while paused IC:263-266, and `movement` is reset by stopMoving so a held key does not repeat on resume (browser repeat events ignored IC:151). Soft-drop interval self-stops IC:292-295 but heldKeys keeps KeyS; updateSoftDrop is called only from KeyS key events IC:162 and processInput IC:230, so a held keyboard S is not restarted on resume, while a held pad-down is restarted at the next poll IC:230 (padDown recomputed each frame). Releasing a different direction after resume calls resumeHeldMovement IC:157/239, which restarts repeat for a still-held key/pad direction IC:246-248.
7.4 Touch (compare D33 C2, D34 E1): drag.moved is set once beyond 10 px SC:448-449 and never cleared before resetDragState SC:490, so a touch that exceeded 10 px and returned within 10 px does not rotate (SC:488). pointercancel resets without rotating SC:493-494,486-491. Rotation is committed at pointerup SC:489 (op 9). Whether tap threshold is checked at end distance: code tests only !drag.moved, i.e. "never beyond 10 px" (hypotenuse test SC:448, strict < comparison), not an explicit end-distance test.
7.4a pointerdown has no state check SC:431-438: a touch begun while paused/over still creates drag.piece; moves/drops/rotate then go through engine guards which no-op when not playing (GM:540,551,560,584; dropTetromino GM:245 not read for guard).
7.4b visibilitychange resets drag state SC:546 but does not call releaseAllInput; blur calls releaseAllInput IC:87 but not resetDragState.
7.5 Confirmation keys: while GM.isConfirmingNewGame, handleKey updates heldKeys IC:126-127 before the confirm branch returns IC:145, so keys pressed during the dialog count as held. Enter during the dialog is not handled in IC:135-146 and is left to the focused dialog button (browser click -> SC:519/520).
7.6 Gamepad: only the first connected pad is read IC:173; processInput runs every frame IC:109,181 with deduplicated actions IC:225; Menu and View act alone IC:214-222 (matches comment IC:210-213).
7.7 Input timers (IC:268/270/291) bypass the engine Scheduler and GM.schedule/guard; bodies are not invariant-checked, though their engine calls are. (Relevant to D22/D23 SAF-4 timer scope and D27 scheduler trust decisions - not interpreted here.)
7.8 Dedup in PAD_ACTIONS IC:223-226: b and rb both map rotate; a and up both map drop; one action per frame per distinct action.
7.9 Keyboard KeyP/Escape and gamepad Menu both route to togglePause; key Escape while dialog -> cancelNewGame IC:138 (not togglePause).
