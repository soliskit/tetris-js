## Parser density, not raw-format adoption

Under normal array iterators, for-of visits each index including a hole as undefined; unlike every/forEach it does not omit an absent index. A missing outer row fails Array.isArray(row). A missing inner cell fails isObject(cell). Successful parseBoard iterations push a fresh cell object per column into a fresh cells array, then push that row into a fresh result. The exact length checks and successful visits therefore yield20own rows with10own cells each, even though input-object identity is not retained. If a numeric property were inherited, lookup could obtain it; the stated no-inherited-substitute premise is needed for the stronger claim that input holes reject. Output construction remains a different observation.
